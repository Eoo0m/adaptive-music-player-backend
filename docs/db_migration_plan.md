# DB 테이블 분리 마이그레이션 계획

## 배경
`track_embeddings` 한 테이블에 메타 + 벡터 3종이 있어 행이 무거워 (~3KB+) 배치 UPDATE 시 DB 크래시 발생.
→ `tracks` (메타) + 벡터 테이블 3개로 분리.

---

## 목표 구조

```
tracks                    ← 메타만 (가벼움)
  id, track_key (UNIQUE)
  title, artist, album, cover_image_url
  isrc, apple_music_id, playlist_count

track_vectors_simgcl      ← embedding vector(64)
  track_key (PK, FK → tracks)

track_vectors_clip         ← projected_embedding vector(512)
  track_key (PK, FK → tracks)

track_vectors_twotower     ← itemtower_embedding vector(128)
  track_key (PK, FK → tracks)
```

---

## Phase 1 — 새 테이블 생성 (무중단)

```sql
CREATE TABLE tracks (
    id              bigint PRIMARY KEY GENERATED BY DEFAULT AS IDENTITY,
    track_key       text NOT NULL UNIQUE,
    title           text,
    artist          text,
    album           text,
    cover_image_url text,
    isrc            text,
    apple_music_id  text,
    playlist_count  int DEFAULT 0
);

CREATE TABLE track_vectors_simgcl (
    track_key text PRIMARY KEY REFERENCES tracks(track_key) ON DELETE CASCADE,
    embedding vector(64) NOT NULL
);

CREATE TABLE track_vectors_clip (
    track_key           text PRIMARY KEY REFERENCES tracks(track_key) ON DELETE CASCADE,
    projected_embedding vector(512) NOT NULL
);

CREATE TABLE track_vectors_twotower (
    track_key           text PRIMARY KEY REFERENCES tracks(track_key) ON DELETE CASCADE,
    itemtower_embedding vector(128) NOT NULL
);
```

## Phase 2 — 데이터 복사 (무중단, 읽기 작업)

```sql
-- 2-1. 메타 복사 (tracks 먼저)
INSERT INTO tracks (id, track_key, title, artist, album, cover_image_url, isrc, apple_music_id, playlist_count)
SELECT id, track_key, title, artist, album, cover_image_url, isrc, apple_music_id, playlist_count
FROM track_embeddings;

-- 시퀀스 재설정
SELECT setval(pg_get_serial_sequence('tracks', 'id'), (SELECT MAX(id) FROM tracks));

-- 2-2. SimGCL
INSERT INTO track_vectors_simgcl (track_key, embedding)
SELECT track_key, embedding FROM track_embeddings WHERE embedding IS NOT NULL;

-- 2-3. CLIP
INSERT INTO track_vectors_clip (track_key, projected_embedding)
SELECT track_key, projected_embedding FROM track_embeddings WHERE projected_embedding IS NOT NULL;

-- 2-4. Two-Tower
INSERT INTO track_vectors_twotower (track_key, itemtower_embedding)
SELECT track_key, itemtower_embedding FROM track_embeddings WHERE itemtower_embedding IS NOT NULL;
```

**검증:**
```sql
SELECT
    (SELECT COUNT(*) FROM track_embeddings)         AS original,
    (SELECT COUNT(*) FROM tracks)                   AS tracks_cnt,
    (SELECT COUNT(*) FROM track_vectors_simgcl)     AS simgcl_cnt,
    (SELECT COUNT(*) FROM track_vectors_clip)       AS clip_cnt,
    (SELECT COUNT(*) FROM track_vectors_twotower)   AS twotower_cnt;
```

## Phase 3 — 인덱스 생성 (무중단)

```sql
-- tracks 메타 인덱스
CREATE INDEX idx_tracks_artist_btree ON tracks (lower(artist) text_pattern_ops);
CREATE INDEX idx_tracks_isrc ON tracks (isrc) WHERE isrc IS NOT NULL;
CREATE INDEX idx_tracks_apple_music_id ON tracks (apple_music_id) WHERE apple_music_id IS NOT NULL;

-- HNSW 인덱스 (기존과 동일 파라미터)
CREATE INDEX idx_simgcl_embedding_hnsw
ON track_vectors_simgcl USING hnsw (embedding vector_cosine_ops)
WITH (m = 32, ef_construction = 200);

CREATE INDEX idx_clip_projected_hnsw
ON track_vectors_clip USING hnsw (projected_embedding vector_cosine_ops)
WITH (m = 16, ef_construction = 64);

CREATE INDEX idx_twotower_itemtower_hnsw
ON track_vectors_twotower USING hnsw (itemtower_embedding vector_cosine_ops)
WITH (m = 16, ef_construction = 64);
```

> HNSW 인덱스 생성은 데이터 크기에 따라 수~수십 분 소요.

## Phase 7 — 모니터링 후 구 테이블 제거

배포 후 수 시간~하루 이상 이상 없으면:

```sql
-- FK 참조 확인 먼저
SELECT tc.table_name, kcu.column_name
FROM information_schema.table_constraints tc
JOIN information_schema.key_column_usage kcu ON tc.constraint_name = kcu.constraint_name
JOIN information_schema.referential_constraints rc ON tc.constraint_name = rc.constraint_name
JOIN information_schema.table_constraints tc2 ON rc.unique_constraint_name = tc2.constraint_name
WHERE tc.constraint_type = 'FOREIGN KEY' AND tc2.table_name = 'track_embeddings';

-- 이상 없으면 DROP
DROP TABLE track_embeddings CASCADE;
```

## 주의사항

1. **데이터 동기화 윈도우**: Phase 2 복사 ~ Phase 6 배포 사이에 배치 작업(매핑 스크립트) 중지 필요
2. **HNSW + JOIN 실행 계획 검증**: 배포 후 `EXPLAIN ANALYZE`로 HNSW 인덱스가 제대로 타는지 확인
3. **WITH 절 패턴**: `home_feed.py`, `playlist_builder.py`의 CTE 패턴은 HNSW 인덱스를 못 탈 수 있으므로 반드시 2-step으로 변경
4. **FK 확인**: `user_favorites`, `user_action_logs` 등이 `track_embeddings`를 FK로 참조하는지 DROP 전 확인
